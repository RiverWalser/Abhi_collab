Q6. How much time does our visited boards tracking save us? Run the solver on the "half-done" board in the res folder and
note at the bottom of the screen how many boards it said it tried.
Now comment-out your code that skips already-visited boards and run the experiment again. Give the two counts
and explain the results. Would you expect the percentage gap between the two counts to be same/greater/less if
you re-run this experiment starting with the whole board? (try it if you dare!)

With visited-board tracking, the solver explored 1,742 boards in 8 ms. Without visited-board tracking, it explored 21,364 boards in 100 ms. So a 91.85% reduction in boards explored.

By tracking previously explored unsuccessful configurations, the solver can  avoid exploring the same branches repeatedly.

I would expect the percentage reduction to generally be greater with the full board because there are more possible move sequences and more opportunities to reach the same configuration through different paths. But, this is not neccicarily true because the solver stops as soon as it finds a solution.
